2. Từng bước trong một vòng

A1–A2

Đọc Trace Log và Build ①

brain.py · context_manager.build · validation.derive_hypothesis_status

  • Lấy mọi evidence của phiên, nhóm theo hypothesis_id.
  • Sắp evidence theo độ tin cậy: traffic > PR > source > docs. Evidence cũ (stale) bị đẩy xuống.
  • Tính trạng thái từng hypothesis (bảng ở mục 3).
A3

Normalize

context_manager.normalize

  • Ước lượng token = số ký tự / 4.
  • Vượt 70% của 200.000 token thì bỏ dần evidence kém tin cậy nhất. Thực tế chưa lần nào chạm ngưỡng này.
A4

Format context gửi model

context_manager.format_context

  • goal: toàn bộ hồ sơ escalate của Tầng 1, cộng escalation_reason, identity_key (v2), tier1_window_daysv3.
  • available_tools: tên, mô tả và schema input của 4 tool.
  • hypotheses: id, statement, polarityv3, status, danh sách evidence kèm stance.
  • system_notices: thông báo từ vòng trước (bị từ chối, trùng lệnh, lỗi tool...).
  • system_instruction: hướng dẫn polarity, cảnh báo code sinh từ .proto, gợi ý keyword, luật cửa sổ trafficv3. bảo mật: evidence bọc trong thẻ <evidence>
A5

Agent Runtime → Model

agent_runtime.py · llm/client.py · llm/schemas.py

  • Dựng JSON schema output mỗi vòng: tên tool chỉ được chọn trong danh sách; đủ 4 hypothesis thì bỏ hẳn trường new_hypotheses.
  • Client (OpenAI hoặc Anthropic) thêm system prompt, ép model gọi đúng function submit_model_output, temperature=0v3.
  • Output sai schema thì gọi lại 1 lần kèm notice; lần 2 vẫn sai thì báo lỗiv3.
  • Token mỗi lần gọi được ghi vào bảng llm_usage.
Output

Model trả về gì

ModelOutput (models.py)

  • reasoning: lập luận dạng văn bản.
  • stance_updates: [evidence_id, support | contradict].
  • new_hypotheses: [id, statement, polarity pro | conv3].
  • tool_calls: [tool_name, tool_input, hypothesis_id].
  • action: call_tool | conclude.
B1

Áp stance

brain.py · storage.update_stance

  • evidence_id không tồn tại: từ chối, ghi notice.
  • Stance ngoài {support, contradict}: từ chối, ghi notice.
  • Evidence là kết quả không tìm thấy (no_match): từ chối stance, ghi notice "trung tính"05/11.
  • Hợp lệ: Brain ghi stance vào Trace Log. Context Manager không ghi gì.
B2–B3

Trần tool call và hypothesis mới

brain.py

  • Quá 4 tool call mỗi vòng thì cắt phần dư, ghi notice "anomaly".
  • Hypothesis mới bị từ chối nếu: đã đủ 4 hypothesis mở, trùng id, hoặc không có tool call nào gắn với nó trong cùng vòng.
  • Lưu Hypothesis(id, statement, polarity)v3.
B4

Chạy tool call

brain.py · tool_registry.validate_input / execute

  • hypothesis_id không tồn tại: từ chối.
  • validate_input (bảng 4 tool ở mục 4). Lỗi thì ghi dòng ERROR vào Trace Log và ghi notice.
  • Trùng tool và input đã chạy: không chạy lại, ghi notice.
  • Cùng lệnh lỗi 2 lần liên tiếp thì bị khoá.
  • Chạy thành công: bảo mật: sanitize, check_injection → cắt còn 4000 ký tự → ghi Trace Log, stance để trống. Model sẽ gán stance ở vòng sau.
B5–B6

Build ② và Observer

context_manager.build · observer.check

Observer dừng phiên theo thứ tự ưu tiên:

  • admin hủy thủ công;
  • đủ 8 vòng;
  • quá 300 giây;
  • "cạn tool": model chọn call_tool nhưng không lời gọi nào thật sự chạy;
  • model chọn conclude.
B7–B8

Trạng thái cuối và lưu

validation.derive_final_statuses · result_formatter · storage

  • Tính final_status và original_agent_status (cây quyết định ở mục 3).
  • Ghi agent_rounds: reasoning, stance, hypothesis mới, action, notices, stopped_by.
  • Dừng thì phase = CONCLUDED, trả RoundResult về cho Orchestrator.
